# Instructor Guide – Module 2.8.1 – Local Intelligence Requirements and Priorities

**Estimated Time:** 15–20 minutes  
**Delivery Method:** Instructor-led orientation and discussion

## Purpose

Teach learners how to orient themselves to the organization's **actual current priorities** rather than treating a classroom example or stale document as local policy.

This module intentionally has no external reference that can supply the answer. The source of truth is the organization's authoritative local requirements/priorities process.

## Learning Objectives

1. Locate and verify the current local intelligence requirements/priorities.
2. Align work to a stated requirement or identify that alignment is not yet verified.

## Suggested Timing

| Part | Time |
|---|---:|
| Why local priorities matter | 3 min |
| Find the authoritative source | 5 min |
| Verify currency | 4 min |
| Align analytic work | 4 min |
| Knowledge check | 3 min |

## Detailed Teaching Notes

### Explain why the local source matters

The learner already knows what an intelligence requirement is from 2.1.4.

This lesson is operational onboarding:
- where is the current list?
- who owns it?
- how do I know this is the current version?
- how do I map today's work to it?

### Treat currency as part of the skill

A stale list can misdirect otherwise good analysis.

Ask learners what evidence would convince them that a requirements document is current:
- effective date;
- version;
- owner confirmation;
- approved workspace;
- supersession notice.

### A12 is useful as an alignment exercise

Do not declare that A12 is itself a PIR.

Instead:

1. show a local requirement if the instructor has an authorized overlay;
2. ask whether A12 supports it;
3. require the learner to explain the connection.

If no real/local overlay is provided, the passing answer is:

> Current priority alignment not yet verified because the authoritative list has not been provided.

### Use blanks as onboarding prompts

The module's orientation table is intentionally incomplete. Filling the blanks from the organization's real process is the learning objective.

## Common Student Challenges

| Challenge | Coaching response |
|---|---|
| Treats active incident = PIR. | Separate operational urgency from formal requirement status. |
| Uses last quarter's list without checking. | Ask how they verified that it is still in force. |
| Invents a classroom PIR ID. | Replace it with “alignment not yet verified” and identify the missing source. |
| Finds a list but not its owner. | Require owner/version context so the learner can judge currency later. |

## Knowledge Check – Answer Key

1. Priorities change; the analyst must confirm the list is still authoritative/current.
2. Record that current priority alignment has not yet been verified.
3. Source/location, owner, current version/effective date, review cadence/status, and the specific requirement used for alignment.

## Transition

Next, learners perform the same orientation exercise for the shop's production, review, approval, and archive workflow.
