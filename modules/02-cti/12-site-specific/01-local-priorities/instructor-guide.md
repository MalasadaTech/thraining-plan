## Module Overview for Instructors

**Purpose of this module:**  
Obtain the shop’s current PIR / priority list and align work only to a stated item — or write that the list is missing. Do not invent a classroom list.

**Context (plain language):**

- What this lesson is for: CTI analysts obtain the shop’s current priorities so analysis answers what leadership already ranked, not whatever looks interesting today. Get the list that is in force here, then say whether a piece of work belongs on it.
- How it hooks to the lesson before: 2.11.3 answered the RFI. Local queue and priority policy was left as obtain-and-follow.
- How it hooks to the lesson after: 2.12.2 is the local produce / approve / archive path.
- Why we are doing it this way: every organization and section has its own list. PIR *concept* is already 2.1.4. This lesson is the current local list, not a rewrite of how to write a requirement.
- What we are *not* doing in this lesson: writing PIRs (2.1.4), inventing a DYA PIR list or priority wording, collection planning (2.1.8), the produce/approve path (2.12.2), no lab.
- Extra step: none. If you overlay a real shop list, say it is overlay for the room, not DYA policy.

Use the same names as the student guide: **current PIRs / priorities**, **stated** local requirement, **obtain-and-follow**, and **I do not have the list yet.** **A12** is desk work (an open incident), not a PIR. Do not treat a user-VLAN or workstation fact as a published DYA priority.

**Key Teaching Points:**
- The current list is obtained, not invented. This course does not publish DYA’s.
- Local requirements drive focus: a stated item gets analysis; interesting is not assigned.
- “I do not have the list yet” is a passing answer. Alignment requires a stated item.

**Common Student Challenges:**
- Invent a PIR ID so the page is not blank. Why: 2.1.4 taught how a requirement looks, and this lesson asks for current items. Example: writing a classroom PIR ID as if it were shop policy.
- Treat **A12** as the priority list. Why: it is the open incident on the desk. Example: “A12 is on user workstations, so that is the PIR.”

## Detailed Teaching Notes

### 1. Key Concepts

**Talking Points:**
- Open with the job: analysis has to follow what this shop ranked, so the first move is to obtain the current list.
- A PIR is a ranked requirement (2.1.4). Today is this shop’s current list, not how to write one.
- Every organization and section has its own. A new analyst obtains it early. The current list is the one in force now.
- Walk obtain-and-follow. If you overlay a real shop list, name it as overlay, not DYA policy.
- Drive focus: stated item gets analysis. Interesting-but-unlisted is not assigned. Without a list, nobody can claim alignment.
- Walk the two products from the student guide: identify the current items, or write “I do not have the list yet.” Align only to a stated item. A12 is an incident, not a PIR.
- If they write a classroom PIR ID: that is invented. Fail that product.
- If they start a produce/approve chain or a collection plan: that is 2.12.2 / 2.1.8.

## Knowledge Check – Answer Key

1. **You should invent a DYA PIR list so the class has numbers. True or false?**  
   **Answer:** False.  
   **Explanation:** Every shop has its own list. This course does not publish DYA’s. Obtain the current list; do not invent one.

2. **What do you write if the shop has not given you the current list?**  
   **Answer:** **I do not have the list yet.** Ask the lead where it lives.  
   **Explanation:** Identifying current priorities starts with obtaining the list. “Not yet” is a pass. Inventing IDs is not.

3. **You have not been shown a current list. Can you mark A12 as aligned to a local requirement?**  
   **Answer:** No.  
   **Explanation:** Alignment requires a stated item on a list you were shown. A12 is an open incident, not a PIR. Without the list, write that you do not have it yet.
