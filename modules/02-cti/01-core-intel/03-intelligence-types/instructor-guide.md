## Module Overview for Instructors

**Purpose of this module:**  
Classify a product or requirement as strategic, operational, tactical, or technical. Reject the neighbor.

**Context (plain language):**

- What this hour is for: CTI analysts match the answer to the decision the consumer can make.
- How it hooks to the hour before: 2.1.2 was the stage. Type is not a stage.
- How it hooks to the hour after: 2.1.4 is writing the requirement. This hour is only the type of answer.
- Why we are doing it this way: Short 0.x / 4.x voice. Outline a–d. Type follows the question.
- What we are *not* doing this hour: PIR format. Audience rewrite. Actor profile. Invent extra victims. No lab.
- Extra step: none.

Stay on **A12**. Do not invent a second campaign.

**Key Teaching Points:**
- Four types. Neighbor pairs: strategic ↔ operational; tactical ↔ technical.
- Length is not type. A hash is not an action.

## Detailed Teaching Notes

### 1. Key Concepts

Write the four. Walk observables as **technical**, isolate/treat-as-payload as **tactical**.

## Knowledge Check – Answer Key

1. **A long PDF is strategic because it is long. True or false?**  
   **Answer:** False. Type follows the question.  
   **Explanation:** Outline / stay-in.

2. **Four types?**  
   **Answer:** Strategic, operational, tactical, technical.  
   **Explanation:** Outline a–d.

3. **Isolate WS-JLEE; treat the update domain as the A12 payload host. Type and neighbor?**  
   **Answer:** **Tactical.** Not technical: that sentence is the action now, not the observable.
