# Instructor Guide – Module 4.3 – Nominations from SOC, Hunt, and CTI

**Estimated Time:** 15–20 minutes

## Purpose

Teach a low-friction intake model in which nominators communicate the defensive need and evidence while DE owns the technical solution.

## Minimum Classroom Bar

- **Need**
- **Evidence/context pointer**

A drafted rule is optional.

## Outcomes

**Accept:** clear enough for DE to own the next engineering decision.  
**Send back:** likely DE work, but missing evidence/context required to evaluate it.  
**Reject/route:** belongs to another workflow such as investigation, containment, blocking, or training.

## Common Student Challenges

| Challenge | Coaching response |
|---|---|
| Requires a finished rule from SOC/hunt/CTI. | The nominator identifies the need; DE engineers the solution. |
| Accept means “deploy exactly this.” | Accept means take ownership for engineering review. |
| Reject means “ignore it.” | Route a legitimate need to the correct owner. |
| Send-back note is vague. | Name the exact missing evidence or context. |

## Knowledge Check – Answer Key

1. Need + supporting case/report/hunt/evidence pointer.
2. Accept.
3. Send back means the request may be DE work but needs more information; route means another function owns the action.
